# ColorFit 基本設計書

## 1. 文書概要

### 1.1 目的

本書は、Webデザイナー向けWebアプリケーション「ColorFit」の基本設計を定義するものである。

`product.md` で定義したプロダクトコンセプトおよび `01_requirements.md` で定義した要件をもとに、システム全体の構成、ユーザー操作フロー、画面遷移、FrontendとBackendの責務、データフロー、外部サービスとの関係などを定義する。

本書では、システム全体を理解するために必要な基本的な構造を定義し、具体的な実装方法については `03_detail-design/` で定義する。

---

# 2. 基本方針

## 2.1 システム構成方針

ColorFitはFrontendとBackendを分離したWebアプリケーションとして構築する。

```text
┌─────────────────────────────┐
│           Browser           │
│                             │
│   React + TypeScript        │
│   React Router              │
│   Tailwind CSS              │
└──────────────┬──────────────┘
               │ HTTPS / API
               ↓
┌─────────────────────────────┐
│          Backend            │
│                             │
│   Python + FastAPI          │
│   Image Processing          │
│                             │
│   Pillow / NumPy            │
└──────────────┬──────────────┘
               │
       ┌───────┴────────┐
       ↓                ↓
┌─────────────┐  ┌─────────────┐
│ Cloudflare  │  │ 外部サービス │
│     R2      │  │    etc.     │
└─────────────┘  └─────────────┘
```

Frontendはユーザーインターフェースとユーザー操作を担当し、Backendは画像解析・画像処理などのサーバー側処理を担当する。

---

# 3. システム全体構成

## 3.1 システム構成

MVPでは以下の構成を基本とする。

| 項目             | 技術 / サービス    | 主な役割                 |
| ---------------- | ------------------ | ------------------------ |
| Frontend         | React + TypeScript | UI・ユーザー操作         |
| Routing          | React Router       | 画面遷移                 |
| Build            | Vite               | Frontendビルド           |
| Styling          | Tailwind CSS       | UIスタイリング           |
| Animation        | GSAP               | UIアニメーション         |
| Backend          | Python + FastAPI   | API・画像処理            |
| Image Processing | Pillow / NumPy     | 画像解析・変換           |
| Storage          | Cloudflare R2      | 一時画像・生成画像の保存 |
| Frontend Hosting | Vercel             | Frontendデプロイ         |
| Backend Hosting  | Render             | Backendデプロイ          |
| Source Control   | GitHub             | ソースコード管理         |

# 4. Frontend

## 4.1 Frontendの責務

Frontendは以下を担当する。

- UIの表示
- ユーザー入力
- フォーム操作
- カラーピッカー
- 配色比率の操作
- 画像アップロードUI
- 画像プレビュー
- Before / After UI
- 手動調整UI
- プリセット選択
- APIとの通信
- 処理状態の表示
- エラー表示
- 設定画面
- レスポンシブUI
- UIアニメーション

Frontendでは画像処理の主要ロジックを担当しない。

基本技術は以下とする。

```text
React
TypeScript
React Router
Vite
Tailwind CSS
GSAP
```

```text

     ↓
調整値変更
     ↓

```

手動調整の具体的な数値範囲については詳細設計で定義する。

# 19. 状態管理の基本方針

ColorFitでは、以下のような状態をFrontendで管理する。

### アプリケーション状態

- 現在の画面
- 設定値
- UI設定

### エディター状態

- 配色情報
- 配色比率
- アップロード画像
- 調整値
- プリセット
- Before / After状態
- 処理状態

### 結果状態

- 調整済み画像
- 使用した配色
- 調整値
- 書き出し設定
- 書き出し状態

状態管理ライブラリの採用については、アプリケーション規模を確認したうえで詳細設計時に決定する。

MVPでは、不要にグローバル状態を増やさないことを基本方針とする。

# 21. エラー処理の基本方針

エラーは以下のカテゴリに分類する。

```text

    ↓
```

```text
03_detail-design/06_error-handling.md
```

# 22. セキュリティの基本方針

ユーザーが画像をアップロードするため、以下を基本方針とする。

- ファイル形式を検証する
- MIME Typeを検証する
- ファイルサイズを制限する
- 画像の実体を検証する
- 不正なファイルを画像処理へ渡さない
- APIへの不正アクセスを考慮する
- CORSを適切に設定する
- 秘密情報をFrontendへ公開しない
- 不要な画像を長期間保存しない

詳細は `03_detail-design/07_security.md` で定義する。

# 23. データベースの基本方針

MVPでは、永続的なユーザーデータを必須としない。

そのため、MVPではデータベースを使用しない構成を基本とする。

```text
ユーザー
  ↓
画像処理
  ↓
結果取得
  ↓
書き出し
```

という一時的な処理を基本とする。

将来的に、

- ユーザーアカウント
- プロジェクト
- 履歴
- 保存した配色
- ユーザー設定

などを実装する場合、データベース導入を検討する。

# 29. UIデザインの基本方針

ColorFitのUIは以下のデザイン原則に従う。

- ダークUIを基本とする
- グラスモーフィズムを使用する
- 微細なグリッドを使用する
- シアン / バイオレットをアクセントとして使用する
- 控えめなグローを使用する
- 近未来的だが実用性を優先する
- 情報を詰め込みすぎない
- 画像を主役として扱う
- レスポンシブに対応する
- アクセシビリティを考慮する

詳細なデザインルールは `08_ui-guideline.md` で定義する。

これらは論理的な概念であり、具体的なTypeScript型、Python Schema、DBテーブルなどについては各詳細設計で定義する。

# 33. 処理状態

画像処理では、Frontendが現在の状態を明確に把握できるようにする。

基本状態：

```text
idle
  ↓
uploading
  ↓
uploaded
  ↓
analyzing
  ↓
processing
  ↓
completed
```

エラー時：

```text
error
```

書き出しについても同様に、

```text
idle
  ↓
exporting
  ↓
completed
```

という状態を基本とする。

具体的な状態管理方法についてはFrontend詳細設計で定義する。

# 34. 非機能要件への対応方針

## パフォーマンス

画像処理による負荷を考慮し、FrontendとBackendの責務を分離する。

## セキュリティ

アップロードファイルの検証とAPIの入力検証を行う。

## アクセシビリティ

キーボード操作、コントラスト、ARIA、Reduced Motionなどを考慮する。

## 保守性

FrontendとBackendを分離し、それぞれの責務を明確にする。

## 拡張性

将来的にユーザーアカウント、履歴、複数画像処理などを追加できる構造を目指す。
